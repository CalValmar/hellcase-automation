# AGENTS.md

- This repo is a small Python script plus a read-only stats helper. Run it from the repo root: `python3 daily_reward.py` (Python 3.6+ for f-strings). Verify with `python3 -m unittest -v test_daily_reward`; the tests use a fake API and never call Hellcase.
- All local state lives in two gitignored files: `config.json` (`discord_webhook_url` + `accounts` array of `{username, xsrf, session}`) and `history.json` (successful drops). Both must be `chmod 600`. `daily-reward.lock` and `history.json.tmp` are transient local files, also gitignored. Local captures (`capture.json`, `newbie*.json`, `state.json`) are gitignored too: they contain `auth_code` and a Steam trade link. `config.example.json` is the only tracked template. `username` is a local label used in Discord/history, with no check against the API nickname. Empty/missing label falls back to `user.nickname`.
- Each account gets its own `requests.session()` with its cookies. The `xsrf` token is sent both as the `XSRF-TOKEN` cookie and as the `X-CSRF-Token` header on the claim call. `hellcase_session` expires on logout or ~30 days; edit `config.json` locally when calls start failing.
- The flow was identified from real captures and the site's own `useBoxService` JS: `POST https://api.hellcase.com/user_level/claim_free_case/newbie` returns `open_id`, then `GET https://api.hellcase.com/open/newbie/state` returns `bought` + `weapons[0]`. `GET https://api.hellcase.com/open/newbie` only returns the case page (no drop); it is kept for `user.nickname` and `casename`. Don't execute the script or start the timer as a test: every run claims the free case for every configured account.
- A claim with `status` other than `success` or without `open_id` is a failure. The real API returns `error_message: user_level.reward.already_claim` when the daily free case was already taken (for example from the browser); that gets its own "déjà réclamée aujourd'hui" alert instead of blaming the token. A state with `status` other than `success`, `bought` false, or no `weapons[0].item_name` is reported as "gain non renseigné par l'API". Network/JSON errors alert too. In every case no history row is written. Raw responses are never logged.
- `extract_drop()` reads `weapons[0]` from the state response: `item_name`, `skin_name`, `steam_price_en` (fallback `item_price`), `rarity`, `steam_exterior`, `id`. The old `top_items` approach was a proven dead end — those entries are other players.
- Don't add endpoints that were not verified against the site JS or a real capture. `user.nickname` from `GET /open/newbie` is the only known source for the account label fallback.
- The API has no countdown field. `last_open_date` is not a reliable personal date: in one real capture it did not match the newest `top_items` entry. History uses the local run time instead.
- `daily-reward.lock` + `fcntl` prevent two concurrent runs from opening the same cases. There is deliberately no `Restart=` in the service: a retry could reopen a case. Failures are notified on Discord instead.
- `systemd/` holds user unit templates: `daily-reward.service` (oneshot, waits for network, 10min timeout) and `daily-reward.timer` (`OnCalendar=daily`, `Persistent=true`, `RandomizedDelaySec=2h`). Install them in `~/.config/systemd/user/`; `loginctl enable-linger $USER` is required to run while logged out.
- HTTP calls have a 30s timeout, accounts are separated by a small random delay, and webhook failures are ignored. `stats.py` reads `history.json` only and prints counts and total price per account.
