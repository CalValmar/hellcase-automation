# AGENTS.md

- This repo is a small Python script plus a read-only stats helper. Run it from the repo root: `python3 daily_reward.py` (Python 3.6+ for f-strings). Verify with `python3 -m unittest -v test_daily_reward`; the tests use a fake API and never call Hellcase.
- All local state lives in two gitignored files: `config.json` (`discord_webhook_url` + `accounts` array of `{username, xsrf, session}`) and `history.json` (successful drops). Both must be `chmod 600`. `daily-reward.lock` and `history.json.tmp` are transient local files, also gitignored. `config.example.json` is the only tracked template. `username` is a local label used in Discord/history; when set and different from the API's `user.nickname`, the script sends a Discord warning. Empty/missing label falls back to `user.nickname`.
- Each account gets its own `requests.session()` with its cookies. `hellcase_session` expires on logout or ~30 days; edit `config.json` locally when calls start failing.
- `GET https://api.hellcase.com/open/newbie` really opens the case. Don't execute the script or start the timer as a test: every run opens the case for every configured account.
- A response with `status` other than `success` or `case_is_opened` false is a failure: alert on Discord and skip the history row. Network/JSON errors do the same. Raw responses are never logged: they contain `auth_code` and a Steam trade link.
- `extract_drop()` matches drops in `top_items` filtered by the response's `user.id`. It carries a `shortcut:` comment because the real drop field has not been confirmed yet. Until a real capture is supplied, `weapon`/`price` may be null.
- The response's `user` object is the only known source of account info (nickname, id, wallet) — no separate read-only account API was found. Don't add an unverified endpoint.
- `daily-reward.lock` + `fcntl` prevent two concurrent runs from opening the same cases. There is deliberately no `Restart=` in the service: a retry could reopen a case. Failures are notified on Discord instead.
- `systemd/` holds user unit templates: `daily-reward.service` (oneshot, waits for network, 10min timeout) and `daily-reward.timer` (`OnCalendar=daily`, `Persistent=true`, `RandomizedDelaySec=2h`). Install them in `~/.config/systemd/user/`; `loginctl enable-linger $USER` is required to run while logged out.
- The HTTP call has a 30s timeout, accounts are separated by a small random delay, and webhook failures are ignored. `stats.py` reads `history.json` only and prints counts and total price per account.
